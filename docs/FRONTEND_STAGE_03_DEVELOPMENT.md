# 第 3 阶段前端开发技术文档｜Agent 交互、取消与恢复

> 状态：代码与自动化测试完成；长录音真人验收仍待目标设备。

## 1. 本阶段目标

录音任务进入排队、处理中、等待核对、失败、取消或断线时，页面不猜测任务结果；用户能够理解当前状态，并在刷新或暂时断网后继续恢复同一任务。

## 2. 范围

### 包含

- 统一任务状态映射。
- 页面不可见时降低轮询频率。
- 临时断线有限退避重试，并显示“任务未必停止”。
- 真实后端取消与仅停止浏览器识别的文案区分。
- 低置信转录的人工确认门槛。
- 音频任务 ID 随版本化训练草稿恢复。

### 不包含

- 不实现全双工对讲、TTS 或打断播放。
- 不新增任务中心、多用户历史或云同步。
- 不把浏览器 SpeechRecognition 结束解释成后端取消。

## 3. 状态行为

| 前端状态 | 页面反馈 | 用户动作 |
|---|---|---|
| `submitting` | 正在上传录音 | 等待或真实取消 |
| `queued` | 已受理，等待识别 | 可以离开，任务 ID 保留 |
| `running` | 显示转换/识别阶段和进度 | 等待或取消 |
| `waiting_user` | 转录置信度不足 | 核对并确认后评分 |
| `disconnected` | 任务可能继续，正在恢复查询 | 等待或稍后刷新 |
| `failed` | 显示原因和是否可重试 | 重新录制或重试 |
| `cancelled` | 明确已由后端取消 | 重新开始 |
| `stale` | 未知状态，不猜成功 | 刷新并重新读取事实 |

## 4. 实现方案

- `waitForAudioTask` 在网络错误时最多有限恢复，不创建新任务。
- 页面隐藏时轮询最少间隔提高到 5 秒；完成、失败、取消后停止。
- 连续查询失败进入 `disconnected`，保留原任务 ID；只有终态失败、取消或 404 才清除恢复入口。
- 后端 `DELETE /api/audio/tasks/{id}` 成功后才显示真实取消。
- 低置信结果继续保存 `needsConfirmation`，未经确认禁止进入评分。

## 5. 测试与验收

- 单元测试验证：断线一次后恢复同一任务，只调用同一任务查询接口。
- 单元测试验证：音频任务 ID 刷新后仍存在，麦克风活跃状态不会被错误恢复。
- 单元测试验证：浏览器实时识别意外结束可有限自动恢复，主动停止不会重新开启。
- 浏览器 E2E 验证页面 Console 无错误；没有在无人授权时自动开启麦克风。

## 6. 风险与回退

- 浏览器挂起标签页会延迟轮询，但不会重复创建任务。
- 服务重启会把处理中任务标为可重试失败，不能从本地继续原音频媒体。
- 若统一状态层出现回归，业务模块仍保留后端原始状态用于诊断，但 UI 不直接暴露内部错误。
