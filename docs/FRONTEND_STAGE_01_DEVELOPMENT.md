# 第 1 阶段前端开发技术文档｜可运行基础骨架

> 状态：已完成。前置阶段 0“适配与契约”已完成。  
> 本文是下一开发阶段的执行与验收依据，不改变已确认产品评分规则。

## 1. 本阶段目标

用户继续使用现有单屏训练流程，但页面拥有统一、可恢复、可测试的请求和任务状态基础；出现等待、失败或断线时，用户能明确知道发生了什么以及下一步怎么做。

## 2. 范围

### 2.1 本阶段包含

- 页面：知识导入页与 v0 训练代表页。
- 前端基础：TypeScript strict 配置、统一 API 客户端、统一错误类型、任务状态映射、语义设计变量。
- 交互组件：提交状态、任务状态、内联错误、步骤指示和恢复提示的统一规则。
- 接口：知识生成、语音健康、短音频转录、长音频任务、语义健康和语义评估。
- 任务状态：`idle / submitting / queued / running / streaming / waiting_user / succeeded / failed / cancelled / disconnected / stale`。
- 产物：训练卡、转录稿、时间戳停顿证据、语义评估和综合结果。
- 工程检查：Lint、TypeScript、单元测试、静态构建检查和浏览器核心闭环。

### 2.2 本阶段不包含

- 不整体迁移 Next.js、React 或 Tailwind。
- 不重新设计页面风格，不创建第三套视觉方案。
- 不新增登录、云同步、数据库、支付、埋点或生产部署。
- 不实现全双工语音和 TTS 播报。
- 不把没有 Key 的规则结果标成真实 AI。

## 3. 用户流程

1. 用户打开内容入口，选择预训练知识或导入自己的资料。
2. 提交后按钮进入明确加载状态；失败时保留输入并显示恢复方式。
3. 用户进入训练代表页，页面根据已有草稿显示“继续”或“开始”。
4. 用户录音后，前端根据后端任务状态显示上传、排队、识别、核对或失败。
5. 低置信转录进入人工确认，确认后才允许评分。
6. 用户完成两轮并看到综合结果；刷新后可以恢复未完成训练。

## 4. 页面状态矩阵

| 页面/模块 | 初始 | 加载/提交 | 空 | 运行 | 等待确认 | 成功 | 失败 | 恢复 |
|---|---|---|---|---|---|---|---|---|
| 知识导入 | 示例与输入入口 | 禁用重复提交，显示正在生成 | 资料为空时显示字段提示 | 普通短请求，不伪装后台任务 | 用户确认两轮训练卡 | 显示来源、两轮内容和进入训练 | 保留原资料，显示错误与重试 | 已生成卡在同一会话可继续 |
| 训练选择 | 预训练推荐或导入知识 | 读取导入卡和草稿 | 无可用内容时给导入/随机入口 | 不适用 | 确认训练内容 | 进入第一轮 | 内容损坏时安全回退 | 显示继续或放弃草稿 |
| 语音转述 | 文字与麦克风入口 | 请求权限或上传分段 | 无文字/音频不允许提交 | 显示排队、转换、识别进度 | 低置信稿必须核对 | 转录稿与证据就绪 | 显示是否可重试，保留可恢复内容 | 按任务 ID 重新查询 |
| 语义分析 | 显示当前轮次 | 禁止重复请求 | 无有效作答直接走零分规则 | 仅在真实服务运行时显示分析中 | AI 先指出问题并邀请重说 | 展示分项证据和建议 | 无模型显示“本地暂定” | 恢复已确认转录再分析 |
| 综合结果 | 等待两轮完成 | 汇总中 | 任一轮未完成时引导返回 | 不适用 | 不适用 | 显示评分、能力变化和下一步 | 保留已完成轮次 | 刷新从训练档案恢复 |

## 5. 接口契约

### 5.1 统一前端错误

```ts
type AppError = {
  code: string;
  message: string;
  userMessage: string;
  retryable: boolean;
  requestId?: string;
  fieldErrors?: Record<string, string>;
};
```

- 页面只消费归一化后的 `AppError`。
- 超时默认不自动重复创建任务；先查询已有任务状态。
- 401/403、格式错误和无效输入不可自动重试。
- 429、暂时性 5xx 和断线可以有限重试，并展示次数或下一次动作。

### 5.2 接口清单

| 接口 | 作用 | 幂等与重试 | 前端成功状态 |
|---|---|---|---|
| `POST /api/training/from-source` | 从资料生成两轮训练 | 当前非任务式；提交按钮防重 | `succeeded` |
| `GET /api/speech/health` | 判断高精度语音能力 | 可安全重试 | `succeeded/failed` |
| `POST /api/speech/transcribe` | 短音频转录 | 不盲目自动重传 | `waiting_user/succeeded` |
| `POST /api/audio/tasks` | 创建长音频任务 | 阶段内补充客户端请求标识 | `submitting → queued` |
| `PUT .../chunks/{index}` | 连续上传音频分段 | 相同任务和序号不得重复追加 | `submitting` |
| `POST .../complete` | 提交处理 | 重复提交由前后端共同阻止 | `queued` |
| `GET /api/audio/tasks/{id}` | 查询真实状态 | 退避轮询、隐藏页降频 | 状态映射结果 |
| `DELETE /api/audio/tasks/{id}` | 真实取消任务 | 只对未完成任务显示 | `cancelled` |
| `POST /api/semantic/evaluate` | 真实语义判断 | 单轮禁止重复提交 | `succeeded/failed` |

Mock 与真实接口不使用视觉上不可区分的开关：后端不可用时明确进入浏览器转录或本地暂定分析，并显示边界。

## 6. 实现方案

### 6.1 目录与依赖方向

```text
页面 HTML
  ↓
业务模块 editorial / knowledge-studio
  ↓
api-client + task-status + schema guards
  ↓
Python P0 API
```

- 新增集中 API 客户端，业务模块不得自行拼基础地址和错误结构。
- 新增任务状态映射，未知后端状态统一变为 `stale`。
- TypeScript 先覆盖 API、错误、任务和训练卡边界，再逐步覆盖页面控制器。
- 现有分析、评分和训练恢复纯函数继续保留，并纳入类型检查范围。

### 6.2 状态来源

- URL：`theme`、`source`、未来可恢复的 `taskId` 或 view。
- 后端：音频任务、真实语义服务状态和真实产物。
- 页面临时状态：当前表单、录音流、倒计时、展开状态。
- Local Storage：版本化训练草稿、成长记录、主题偏好。
- Session Storage：尚未进入训练的导入训练卡；不得保存密钥或伪造后端任务完成。

### 6.3 响应式、无障碍和单屏约束

- 390、768、1280、1440px 均能完成选择、阅读、转述和确认。
- 页面根节点保持单屏；长内容只在当前阶段内容区受控滚动，不通过拉长页面承载新功能。
- 主按钮和图标按钮至少 44×44px；键盘顺序与视觉顺序一致。
- 提交、识别、确认、失败使用文字加状态，不只靠颜色。
- 焦点进入新步骤的标题或首个操作；错误出现时可被辅助技术识别。
- 减少动态设置下关闭非必要位移和闪动。

### 6.4 安全与隐私

- 浏览器不读取模型 Key；只调用同源 API。
- 错误、日志和测试夹具不记录完整用户语音与私密资料。
- 用户资料作为纯文本渲染，不直接插入不可信 HTML。
- 音频 Object URL 使用后及时释放；离开轮次关闭媒体轨道与识别实例。

## 7. 验收标准

### 7.1 自动检查

阶段完成时必须存在并通过：

```bash
npm run lint
npm run typecheck
npm run test
npm run build
```

- 保持当前 52 项前端与 15 项后端测试不回退。
- 新增错误归一化、未知任务状态、重复提交、断线恢复和移动端关键布局测试。

### 7.2 浏览器验收

1. 打开 `knowledge-studio.html`，使用示例生成训练卡；提交期间不能重复点击。
2. 进入 v0 训练页，确认同一知识包贯穿两轮。
3. 在没有高精度服务时，页面明确显示浏览器转录或文字降级。
4. 模拟任务排队、运行、失败和恢复，页面说明当前发生什么、用户做什么、下一步是什么。
5. 刷新训练页，未完成草稿仍在；没有把本地草稿伪装为后端任务完成。
6. 在 390、768、1280、1440px 检查无横向滚动、主操作可见、步骤可达。
7. 使用键盘走完内容选择、开始、转述确认和下一步；焦点始终可见。
8. Console 无持续错误，Network 无重复创建任务或高频无限轮询。

### 7.3 真实联调边界

- 本阶段至少真实调用知识生成和服务健康接口。
- 麦克风、FunASR、真实语义模型和 3/10 分钟录音仍需对应环境；未完成时单独列为人工验收，不得以 Mock 替代。

## 8. 风险与回退

- 风险：渐进 TypeScript 与现有全局脚本混用时，加载顺序可能变化。处理：先迁移无 DOM 副作用的边界模块，并保留原接口形状。
- 风险：统一错误后页面旧文案可能丢失。处理：过渡期兼容新旧结构并增加回归测试。
- 风险：响应式修正影响桌面单屏密度。处理：每个断点保留截图与可操作验收，不用全局缩放解决。
- 风险：高精度模型不可用。降级：浏览器识别和文字输入始终可用，停顿分明确标为待证据。
- 回退：本阶段按独立模块小步替换；任何新适配层可退回原模块，不迁移用户训练数据 schema。
