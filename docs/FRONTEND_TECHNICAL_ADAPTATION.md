# 语音表达训练｜前端技术适配声明

> 文档状态：已完成阶段 0 适配判断；作为进入前端开发阶段的技术基线。  
> 更新时间：2026-08-30

## 1. 项目判断

- 产品类型：浏览器内完成的 AI 知识理解与口语表达训练工具。
- 主要用户：希望减少口头禅、改善停顿节奏，并提高长文复述与 30 秒速记能力的中文用户。
- 主要终端：桌面 Web 为主，同时要求 390px 手机宽度可完成核心流程；麦克风最终需覆盖 Chrome、Safari 和 iPhone 真人验收。
- 项目状态：已有原生 HTML、CSS、JavaScript 与 Python 本地服务，不是从零项目。
- 本阶段目标：不改变已确认训练逻辑，先建立统一的前端契约、任务状态、工程检查和代表页验收基线。

## 2. 输入资料

- PRD：已读取，见 `PRD_P0_EXPRESSION_TRAINER.md`。
- 通用技术手册：已读取并完成 P0 工程补强。

## 3. 技术选择

### 3.1 本阶段采用

- 运行框架：继续使用当前原生 Web + Python 同源本地服务，避免在业务闭环尚未完成真人验收时整体重写。
- 语言策略：从 API、任务状态和数据校验边界开始渐进迁移到 TypeScript strict；不把一次性全站迁移与业务功能开发混在同一阶段。
- 样式策略：保留现有视觉，通过 CSS 语义变量收口颜色、文本、边框、状态、圆角和阴影；本阶段不引入 Tailwind。
- 组件策略：优先复用已有语义 HTML；仅抽取真实重复的 Button、Status、Error、Step 等模式，不创建万能组件。
- API 策略：建立统一客户端，集中处理基础地址、超时、错误归一化和 JSON 校验；页面禁止继续新增散落 `fetch`。
- 状态策略：URL 保存可恢复的查看位置；后端保存音频任务事实；页面临时状态留在当前会话；主题和非关键偏好保存本地。
- 实时策略：当前高精度长音频采用有节制轮询；浏览器 SpeechRecognition 只作为实时转录降级，不冒充后端任务状态。
- 测试策略：保留 Node 单元测试，增加 TypeScript 类型检查、Lint、静态构建检查和一条浏览器核心闭环。
- 部署策略：当前仍为 localhost 验收；正式 HTTPS 与独立前后端部署留到部署手册阶段。

### 3.2 暂不采用

- Next.js App Router：当前产品只有少量本地单屏入口，整体迁移会同时改动路由、构建、脚本加载和 Python 静态托管，收益尚不足以覆盖回归风险。
- Tailwind CSS：现有样式体系已经形成，先收口语义变量；若后续进入多页面团队开发再评估。
- Zustand、TanStack Query、React Hook Form：当前没有对应的真实复杂度。
- Radix/shadcn：现阶段没有大量复杂弹窗、菜单和组合控件。

## 4. Agent 与语音任务状态

### 4.1 后端音频状态映射

| 后端状态 | 前端统一状态 | 用户看到的含义 |
|---|---|---|
| 尚未创建 | `idle` | 可以开始录音或输入文字 |
| `uploading` | `submitting` | 正在上传录音，禁止重复提交 |
| `queued` | `queued` | 录音已经受理，正在等待处理 |
| `converting` / `transcribing` | `running` | 正在转换或识别，显示真实阶段和进度 |
| 转录增量结果 | `streaming` | 仅在协议真实提供增量时使用 |
| `completed` 且需核对 | `waiting_user` | 用户必须确认转录稿后才能评分 |
| `completed` 且已核对 | `succeeded` | 可以进入表达分析 |
| `failed` | `failed` | 显示可理解错误和是否可重试 |
| `cancelled` | `cancelled` | 任务已经由后端取消 |
| 连续查询失败 | `disconnected` | 任务未必停止，先恢复查询 |
| 未知状态或过期记录 | `stale` | 重新获取后端事实，不能猜测成功 |

### 4.2 确认、取消和恢复

- 等待确认：低置信转录始终进入 `waiting_user`，说明为什么需要核对以及确认后的影响。
- 停止浏览器识别：只停止本地监听，不描述为“取消后端任务”。
- 取消长音频：调用真实 DELETE 接口后才显示 `cancelled`。
- 刷新恢复：训练草稿从版本化本地结构恢复；有音频任务 ID 时重新查询后端状态。
- 重复提交：按钮提交后立即禁用；后续阶段为创建任务补充幂等标识。

## 5. 页面、流程与产物

- 内容入口：`knowledge-studio.html`，导入或选择知识并生成两轮训练卡。
- 代表页面：`concept-editorial.html?theme=v0`，完成选择、阅读、转述、建议、速记、快速转述和综合结果。
- 辅助入口：专项计划、专项考试和成长档案继续作为代表页内部视图，不扩展成额外长页面。
- 核心闭环：选择/导入知识 → 第一轮阅读与转述 → 人工核对 → 表达分析 → 第二轮速记与转述 → 综合结果 → 刷新可恢复。
- 产物：转录稿、停顿证据、两轮分项评分、知识点证据、AI 引导建议、专项计划和成长变化。
- 响应式目标：390、768、1280、1440px；页面外壳不纵向滚动，必要内容只在当前阶段内容区内受控滚动。

## 6. 设计与体验基线

- 继续使用当前克制、内容优先的 v0 视觉，不新增大面积橙色和无业务意义装饰。
- 多步骤流程保留明确步骤指示；提交必须出现加载、成功或错误反馈。
- 核心控件维持至少 44×44px 触控面积、可见键盘焦点和语义名称。
- 状态不只依赖颜色；错误靠近操作位置；关键变化使用适度 `aria-live`。
- 动画只表达步骤切换和状态变化，并尊重 `prefers-reduced-motion`。

## 7. 与前端手册不同的地方

| 偏离项 | 原因 | 影响与处理 |
|---|---|---|
| 不立即迁移 Next.js | 已有单屏原生 Web 流程可运行，整体迁移会扩大回归面 | 先完成真实闭环与工程底线；多页面、账号或正式部署出现后再评估 |
| 不立即使用 Tailwind | 当前已有完整 CSS，直接替换不产生用户价值 | 先落语义变量和状态组件规范 |
| TypeScript 渐进迁移 | 当前约千行交互逻辑为 JavaScript，一次迁移风险高 | 阶段 1 从 API、类型和状态边界开始；新模块禁止无类型扩散 |
| 暂不引入 React 测试栈 | 当前不是 React 项目 | 继续 Node 测试并补浏览器 E2E；迁移 React 时再采用 RTL/Vitest |
