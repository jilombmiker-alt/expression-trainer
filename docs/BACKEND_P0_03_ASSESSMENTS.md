# 后端 P0 · 阶段 03：两轮服务端评分与可追踪记录

日期：2026-09-04。状态：日常两轮评分已接入后端，专项考试、云端成长等级和计划仍未迁移。

## 接口与状态

| 接口 | 职责 |
| --- | --- |
| POST /api/training/runs | 注册同一知识包的两轮材料与默认权重 |
| POST /api/training/attempts | 开始指定轮次，保存模式和本次权重快照 |
| POST /api/training/assess | 冻结提交，调用用户模型，后端重算评分并保存 |
| GET /api/training/records | 当前访客最近 100 次已完成作答 |

第二轮必须已有第一轮完成结果。每个作答有 UUID；模式分 independent/guided/demo。示例填充会创建 demo 作答。原始阅读内容在 run 注册后固定，提交不能携带另一份标准答案覆盖它。

作答状态为：开始 → 提交冻结 → 处理中 → 保存结果；失败释放处理租约但保留原请求。进程中断后 150 秒租约过期可重试。并发处理中返回 409，容量满返回 503。前端重试不产生新作答编号。

## 评分来源

后端调用既有语义服务，随后以 Node 子进程运行 `services/score_worker.cjs`，复用 analyzer、semantic-evaluator、scoring-model，避免 Python/JS 两套规则漂移。Python 不接受客户端传来的 total、components 或模型评价。

Node 是后端必需运行时；可设置 `EXPRESSION_NODE_PATH`。子进程 10 秒超时，不接收 API Key，无 shell 拼接；同时最多 2 个分析任务。模型使用用户 BYOK，不为主训练评分回退到产品方 Key 或静默本地规则。

每轮进入作答时校验权重完整、非负、合计 100%，并锁定本次快照；后续新作答可以切换权重。结果同时存用户权重评分与固定默认权重 baselineScoring。

## 数据与幂等

SQLite 中保留来源材料快照、时间、轮次、模式、权重、提交摘要、正文、逐项证据、用户权重结果、基准结果和模型元数据。相同作答及相同规范化提交返回已保存结果；正文/计时不同返回 409，不覆盖原结果。结果与 assessment_finished 事件在同一事务写入。

成功保存后重复请求不会再次调用模型。进程若在模型已经响应但尚未保存时崩溃，重试可能再次调用供应商；本阶段不承诺供应商费用 exactly-once。

## 成长边界

主训练不再用浏览器自己提交的分数入后端库。示例/引导作答单独标记；暂定反馈不改变本地成长等级或连续记录。可用的独立练习在本地趋势中采用固定基准总分，不因调整权重虚增成长。

当前 `gradeEligible=false` 明确表示不是正式等级认证：材料由用户选入、没有防录音重放校验，正式考试尚在旧本地流程。既有成长档案、专项计划和考试未迁移到服务器，也未把旧数据伪装成已认证记录。

## 验收和后续

已测试服务器不采用伪造 999 分、跨用户记录隔离、重复提交只留一份结果与事件、内容冲突拒绝、模型失败不保存 0、租约恢复、权重校验和轮次顺序。

下一步应迁移考试/成长/计划；给正式题库设版本与难度；将时长不足、语义离题、技术故障分开校准；完善读取/删除/恢复接口。真实模型准确率、音频重放防护、长时任务及并发压测均未验收。
