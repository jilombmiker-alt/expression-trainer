# 后端 P0 · 阶段 01：作答计时与故障边界

日期：2026-09-04。范围：日常训练的两轮转述，不包含专项考试计时迁移。

## 原问题

旧版在等待语义模型返回后才计算 elapsed，使模型等待时间混入作答时间。录后转录等待、权限弹窗与页面重绘也可能影响时长。

## 实现

- `web/answer-timing.js` 分别记录进入作答时间、录音区间累计时间、提交冻结时间。
- 有录音时使用录音区间总时长；纯文字输入使用作答页停留时长，明确标为客户端证据。
- 提交在任何异步请求之前冻结；重复提交复用原时间和正文，不因网络/模型耗时增长。
- 手动停止、识别中断和页面退出关闭录音区间；识别重连开始新区间。
- 更换主题重绘同一作答页不重置计时。返回阅读再作答会创建新作答。
- 后端另存提交前墙钟时间和分析耗时，不把二者合并。
- 对已完成且属于当前访客的服务器音频任务，读取 WAV 实际时长和真实时间戳停顿，不使用浏览器推测的停顿计算后端成绩。
- 缺少可核验音频的结果标 `provisional`。浏览器自报时长受服务器作答窗口上限约束，但仍不等于反作弊证据。
- 模型或评分服务失败，保留草稿、允许重试，不保存 0 分结果。

## 验收

- `web/answer-timing.test.js`：模型等待不增加时长；分段录音排除区间间隔、权限等待、转录及编辑时间。
- `services/test_training_backend.py`：模拟模型耗时 60 秒，作答仍为原 30 秒；故障不产生零分记录。
- Chrome 错误路径：文字保留、按钮恢复可点击、再次提交使用原冻结请求。
