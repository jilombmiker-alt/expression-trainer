# P0 第 5 阶段技术开发文档｜知识生成服务与来源追踪

> 配套文档：`PRD_P0_EXPRESSION_TRAINER.md`、`P0_TECHNICAL_ADAPTATION.md`、AI Agent 产品 Vibe Coding 通用技术栈手册。

## 一、阶段目标

- 把用户资料生成同一知识包中的两轮训练卡。
- 保留来源、知识结构、两轮差异、概念组和挑战维度。
- 不执行资料中的指令，不用来源外常识冒充知识库结论。

## 二、技术适配摘要

- 当前使用后端确定性来源约束规则，优先验证知识训练闭环。
- 没有真实模型时明确“尚未经过 AI 语义改写”。
- OpenKB 只有在真实 wiki 存在时启用，不用示例资料冒充接通。

## 三、技术栈与模型

- Python 知识服务：清理文本、分句、分轮、概念提取和稳定 ID。
- 浏览器本地规则作为服务异常降级。
- P0 未配置知识生成 LLM，也未连接真实 OpenKB。

## 四、环境与配置

- 接口无需密钥；最大请求 1MB，源文本最多约 30000 字。
- 输入至少约 220 个有效字和 4 个完整句子。
- JSON 训练卡可以作为受控文件导入；普通资料按文本数据处理。

## 五、项目结构

- `services/knowledge_service.py`：来源约束生成与校验。
- `web/knowledge-studio.js`：输入、文件读取、服务调用和降级。
- `web/training-card.js`：统一训练卡 schema。
- `skills/expression-knowledge-training/`：知识训练方法与 OpenKB 适配说明。

## 六、数据、资产与状态

- 训练卡包含 schema 版本、稳定 ID、标题、来源模式、来源引用、知识结构、两轮文章、概念组和挑战。
- 第一轮 100–220 字；第二轮 80–160 字；每轮 3–4 个概念组。
- 来源引用进入选择页和阅读页；缺失信息标记为未知。

## 七、API / 工具设计

- `POST /api/training/from-source`：输入主题、资料、关键词和来源名称，返回统一训练卡。
- 结构、长度、句子数量、概念数量、两轮差异和来源字段均在后端校验。
- 错误使用统一结构；浏览器可以在服务不可用时降级，但必须显示生成边界。

## 八、Prompt 设计

- 当前阶段没有 LLM Prompt，生成器标识为 `grounded-rule-v1`。
- 未来接入模型时必须把资料作为不可信数据，强制只使用来源证据并通过训练卡 schema 校验。

## 九、验收界面或纵向切片

- 知识工作台包含添加资料、确认两轮练习和进入训练三个步骤。
- 进入训练后优先选中“我的导入知识”，两轮共用同一知识包。
- 页面显示来源名称和“规则生成 / AI 未校验”边界。

## 十、测试要求

- 后端：两轮差异、来源保留、短资料拒绝和不存在关键词不采纳。
- 浏览器：训练卡规范化、来源元数据、资料作为文本处理和本地降级。
- 外部：真实 OpenKB wiki 路径、节点引用和未知信息处理。

## 十一、验收清单

- [ ] 两轮都来自同一输入资料。
- [ ] 两轮不是同一段文字机械截短。
- [ ] 来源名称可查看。
- [ ] 资料中的指令不会被执行。
- [ ] 资料不足时有可操作提示。
- [ ] 真实 OpenKB 接入后能追踪 wiki 路径。

## 十二、风险与待确认项

- 当前规则提取不等于真实 AI 知识理解。
- 没有真实 OpenKB 实例，OpenKB 连接仍待外部验证。
- PDF、Word、扫描件和大型文档解析不属于当前文本 P0。

## 十三、交接给下一阶段

- 已就绪：同源两轮生成、来源追踪、统一训练卡、页面接入和自动测试。
- 阻塞项：真实 OpenKB 与知识生成模型；未完成前不得声称知识库 AI 已接通。
