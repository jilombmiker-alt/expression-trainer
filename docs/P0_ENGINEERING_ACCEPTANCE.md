# P0 工程验收台账｜前端技术手册阶段前停止点

更新时间：2026-08-30

## 1. 本阶段结论

依据《AI 产品 Vibe Coding 通用技术栈手册》完成现有项目的 P0 工程补强；保持原生 Web + Python 本地服务，不为套用通用模板而提前迁移框架。本文是进入《AI 产品 Vibe Coding 通用前端技术栈手册》之前的停止点。

当前可以确认的是“代码、自动化测试和浏览器验收入口已准备好”；不能把它描述为“真人语音、真实模型和正式上线已经验收”。

## 2. 已通过｜代码和自动化证据

- 产品基线：两轮训练、权重、零分门槛、AI 追问边界已写入 PRD。
- 输入校验：知识、语义、短音频和长音频均有大小、格式或结构校验。
- 音频真实性：WebM、MP4、OGG 检查真实文件头，并拒绝伪造或类型不一致内容。
- 统一错误：API 采用 `error.code / error.message / error.retryable`，页面兼容读取。
- 长任务：分段上传、进度、取消、失败、服务重启恢复边界均有持久化状态。
- 训练恢复：草稿 schema、损坏回退、人工核对点和成长档案隔离已有自动测试。
- 隐私：`.env` 与派生秘密文件被 Git 忽略，仓库只保留空值示例。
- 测试：57 项前端测试、15 项后端测试、TypeScript、Lint、静态构建与 Chrome 核心闭环通过。
- 文档：PRD、技术适配、五阶段技术文档、API 契约、人工验收清单齐全。

## 3. 已建立｜交接与复现基线

- Node 依赖由 `package-lock.json` 固定。
- Python 语音直接依赖的本机已测版本记录在 `services/requirements-speech-tested.txt`；它不是跨平台完整传递依赖锁。
- 无 FunASR 时可用 `npm run web:p0:core` 打开基础服务；高精度语音环境使用 `npm run web:p0`。
- API 与人工验收步骤分别记录在 `P0_API_CONTRACT.md` 和 `P0_ACCEPTANCE_CHECKLIST.md`。
- Git 仓库在本阶段初始化；是否创建正式基线提交由项目所有者决定。

## 4. 待真人或外部环境验收｜不能自动冒充

| 项目 | 当前证据 | 完成条件 |
|---|---|---|
| 麦克风权限与自动恢复 | 逻辑和单元测试通过 | 用户在目标浏览器允许权限并完成 60 秒实说 |
| 停顿准确度 | 时间戳解析与无时间戳降级已测 | 对照人工计时校准 0.8、1.5、2.5 秒停顿 |
| 高精度中文识别 | FunASR 适配代码存在 | 模型完整下载后用真实中文录音冒烟 |
| 真实语义模型 | 无 Key 降级和输出校验已测 | 安全配置模型后测试同义、遗漏、冲突和乱答 |
| 3/10 分钟长语音 | 分段任务状态机已测 | 真人各完成一次，覆盖取消、刷新和失败重试 |
| OpenKB | 来源约束知识服务已完成 | 提供真实 wiki/API 后验证导入与来源追踪 |

## 5. 本阶段明确不做

- 不进入前端手册的 Next.js、TypeScript、Tailwind、组件库或视觉系统迁移。
- 不新增账号、数据库、对象存储、云部署、计费或团队权限。
- 不把规则分析包装成真实大模型结果。
- 不把本地浏览器可用包装成生产可用。

## 6. 进入下一阶段的门槛

产品经理先按人工清单完成目标设备验收并确认核心训练闭环。只有确认需要正式产品化后，才依据前端技术手册评估框架迁移、组件体系、响应式、无障碍和生产部署；本轮在此停止。
