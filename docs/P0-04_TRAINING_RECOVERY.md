# P0 第 4 阶段技术开发文档｜训练状态与确认点恢复

> 配套文档：`PRD_P0_EXPRESSION_TRAINER.md`、`P0_TECHNICAL_ADAPTATION.md`、AI Agent 产品 Vibe Coding 通用技术栈手册。

## 一、阶段目标

- 刷新后恢复选题、轮次、转录、核对状态、结果、权重和后台任务 ID。
- 不自动重开麦克风或计时器，不把待确认结果变成已确认。
- 草稿恢复与成长档案分离。

## 二、技术适配摘要

- P0 单用户本地验收，使用带 schema 版本的浏览器结构化存储。
- 音频任务真实状态由后端任务记录负责；浏览器只保存任务身份。
- 多设备和账号同步暂缓至生产阶段。

## 三、技术栈与模型

- 原生 Local Storage、Session Storage 和确定性序列化。
- 本阶段不调用模型；只保存模型/ASR 已返回的受控结果。

## 四、环境与配置

- 草稿键：`expression.trainingDraft.v1`。
- 导入训练卡使用会话级存储；成长档案使用独立版本化键。
- 浏览器禁用存储或超出额度时安全降级并提示。

## 五、项目结构

- `web/training-session.js`：草稿 schema、保存、读取和损坏处理。
- `web/editorial.js`：状态变更、继续/放弃和恢复后渲染。
- `web/progress-model.js`：等级、记录和专项计划。

## 六、数据、资产与状态

- 训练状态：`selecting / reading / retelling / confirming / analysing / coached / completed`。
- 保存：步骤、选题、两轮转录、核对状态、结果、权重、导入知识和音频任务 ID。
- 不保存：麦克风开启状态、MediaStream、MediaRecorder 或音频 Blob。
- 损坏、未知 schema 或非法状态安全返回选择页，不白屏。

## 七、API / 工具设计

- 本阶段没有新增 HTTP API。
- 恢复后台音频时调用第 3 阶段的 `GET /api/audio/tasks/{id}`。
- 完成、失败、取消后停止轮询并更新草稿。

## 八、Prompt 设计

- 本阶段没有 Prompt。
- 保存的 AI 结果不因页面刷新重新解释或自动升级为已确认。

## 九、验收界面或纵向切片

- 首页出现“继续上次训练 / 放弃草稿”。
- 恢复后保持原步骤和文字，但麦克风与计时保持停止。
- 低置信转录仍显示“我已核对”确认门。

## 十、测试要求

- 自动测试：低置信确认、选择页不存草稿、损坏数据、安全版本和音频任务身份。
- 浏览器测试：转述输入后刷新、继续、放弃和成长档案不被删除。
- 后台任务测试：刷新后重新查询，未知或失败状态给出恢复动作。

## 十一、验收清单

- [ ] 阅读、转述、待确认和分析后刷新均可恢复。
- [ ] 恢复后不会自动录音或倒计时。
- [ ] 待确认结果不能直接评分。
- [ ] 放弃草稿不删除成长档案。
- [ ] 损坏数据不白屏。
- [ ] 无效作答不降低已获得等级。

## 十二、风险与待确认项

- 浏览器存储只适用于当前设备和浏览器；清理网站数据会删除本地草稿。
- 多设备恢复、登录和云同步不属于 P0。
- 当前需要产品经理继续验证更多中断位置，而不只是一条转述草稿。

## 十三、交接给下一阶段

- 已就绪：版本化草稿、损坏回退、确认门和后台任务身份恢复。
- 待交接：产品经理按验收清单覆盖四种状态；生产阶段再设计账号与跨设备恢复。
