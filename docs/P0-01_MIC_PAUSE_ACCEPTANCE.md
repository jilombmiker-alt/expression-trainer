# P0 第 1 阶段技术开发文档｜真人麦克风与停顿校准

> 配套文档：`PRD_P0_EXPRESSION_TRAINER.md`、`P0_TECHNICAL_ADAPTATION.md`、AI Agent 产品 Vibe Coding 通用技术栈手册。

## 一、阶段目标

- 交付浏览器麦克风预检、权限恢复、实时转录、高精度转录入口和停顿校准。
- 打通“用户说话 → 转录稿 → 人工核对 → 停顿证据”的最小链路。
- 不在本阶段证明模型准确率，不把文字输入推算成停顿。

## 二、技术适配摘要

- 采用纵向切片，延续原生 Web 和 Python 本地服务。
- 浏览器实时识别用于即时反馈；FunASR 用于停止后高精度转录和时间戳。
- 实时识别意外结束自动恢复，连续失败有上限；主动停止不会重启。

## 三、技术栈与模型

- 浏览器：MediaDevices、MediaRecorder、Web Speech API（可用时）。
- 后端：Python HTTP 网关、可选 FunASR、ffmpeg 或 imageio-ffmpeg。
- 停顿证据：FunASR 句段时间戳；浏览器识别只记录实际事件间隔并标记证据等级。

## 四、环境与配置

- 本地地址必须为 `localhost` 或 `127.0.0.1`；正式线上必须 HTTPS。
- 可选配置：`FUNASR_MODEL`、`FUNASR_VAD_MODEL`、`FUNASR_PUNC_MODEL`、`EXPRESSION_FFMPEG_PATH`。
- 没有 FunASR 时页面明确降级为浏览器识别和文字输入。

## 五、项目结构

- `web/editorial.js`：录音和转录交互状态。
- `web/live-recognition.js`：实时识别中断决策。
- `web/mic-calibration.js`：权限和停顿校准规则。
- `web/speech-adapter.js`：受控语音接口适配。
- `services/p0_service.py`：转录入口和 FunASR 调用。

## 六、数据、资产与状态

- 状态：`idle / requesting / listening / recovering / processing / ready / error`。
- 浏览器只保存转录、停顿、时间和确认状态，不保存音频 Blob。
- 校准结果只保存停顿统计；高精度任务的音频临时文件处理后清理。

## 七、API / 工具设计

- `GET /api/speech/health`：返回引擎、模型、能力和不可用原因。
- `POST /api/speech/transcribe`：短录音同步转录；校验大小和真实容器类型。
- 长录音使用第 3 阶段的任务接口。
- 错误统一为 `{"error":{"code","message","retryable"}}`。

## 八、Prompt 设计

- 本阶段没有 LLM Prompt。
- 热词只来自当前训练卡的受控概念组，不把任意页面指令发送给语音模型。

## 九、验收界面或纵向切片

- 转述页展示当前模式、录音按钮、时长、最近停顿、转录稿、人工核对和恢复提示。
- 校准弹窗检查安全环境、权限和高精度服务，并提供 0.8、1.5、2.5 秒目标停顿。
- 意外中断显示自动恢复过程，不无提示退回停止状态。

## 十、测试要求

- 自动测试：校准匹配、无时间戳失败、权限恢复、意外结束、主动停止、致命错误、有界重试。
- 真人测试：允许、拒绝、再次允许；安静和轻噪声；60 秒自然表达。
- 真机：Chrome、Safari 和 iPhone 至少各走一次录音链路。

## 十一、验收清单

- [ ] 点击前能看懂当前转录模式。
- [ ] 拒绝权限后有明确恢复入口。
- [ ] 意外结束自动恢复，主动结束不重启。
- [ ] 没有时间戳时不生成停顿分。
- [ ] 低置信结果必须人工核对。
- [ ] 真人停顿和转录结果可以人工核对。

## 十二、风险与待确认项

- Web Speech API 依赖浏览器实现和网络，不能作为稳定的生产 ASR。
- 当前 FunASR 模型环境未完成真人验收；模型下载和设备性能会影响首次启动。
- 浏览器自动化不得代替真人说话，也不主动采集用户环境声音。

- 待交接：产品经理完成真人录音后，停顿与转录证据才能进入正式评分验收。
