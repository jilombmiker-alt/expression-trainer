# P0 验收补强｜技术适配声明

## 1. 产品形态判断

- 产品类型：浏览器内完成的中文知识理解与口语表达训练工具。
- 核心任务：用户阅读两段同主题材料，分别完成长段转述和 30 秒速记转述，系统分析口语习惯、停顿节奏、内容理解和信息关系。
- 核心交互：分阶段确认、麦克风录音、转录稿人工核对、AI 语义判断、训练记录与专项考试。
- 开发路径：延续现有原生 Web + Python 本地服务，采用纵向切片；不为符合通用手册整体重构。
- 当前范围：只补强 P0 可验收性，不增加新视觉方案、账号体系和正式云部署。

## 2. 延续的现有方案

- 原生 HTML/CSS/JavaScript：现有单屏六步训练已经可用，继续小步增强。
- Python 本地网关：已能托管页面并调用 FunASR，继续作为 P0 后端。
- FunASR：满足本地中文转录和时间戳基础能力。
- 浏览器本地存储：P0 继续使用，但必须补充 schema、恢复和损坏处理边界。

## 3. 本阶段触发的模块

- 麦克风权限与停顿校准：由真实语音验收触发。
- 真实语义模型：由同义转述、冲突和遗漏判断触发。
- 可恢复长任务：由 3–10 分钟回答、音频上传和转录触发。
- 训练状态持久化：由刷新恢复和人工确认点触发。
- 知识生成服务：由用户导入资料后生成两轮知识训练触发。

## 4. 偏离或暂缓

- 暂不迁移 FastAPI/Next.js：当前结构足以完成 P0；接口校验、统一错误和测试通过局部模块补足。
- 暂不引入数据库、登录、Docker 和对象存储：P0 为单用户本地验收；正式部署前重新评估。
- Python 继续使用项目当前 3.9.6：本轮不做解释器升级，避免扩大依赖风险。
- 高精度语音采用“近实时分段”而不是首轮即做复杂流式 ASR：先保证可恢复、可观察和准确。

## 5. 强制底线检查

- 密钥与隐私：P0 代码通过；模型 Key 只由后端环境读取，`.env` 已加入忽略列表并保留无秘密的 `.env.example`。真实模型配置仍待用户提供。
- 数据与任务可恢复：P0 代码通过；长音频任务、训练草稿和人工确认点均有版本化恢复结构。真实服务重启与长录音仍待真人验收。
- 输入输出校验：语义、知识训练和音频任务已有受控校验；WebM、MP4、OGG 会检查真实文件头，声明格式和真实内容不一致时拒绝处理。
- 错误与日志边界：接口统一返回 `error.code / error.message / error.retryable`，页面同时兼容旧错误格式，避免原始异常直接暴露给用户。
- 测试与真实模型验收：57 项前端测试、15 项后端测试和 Chrome 核心闭环通过；真人麦克风、真实语义模型和 3/10 分钟长音频仍待验。

## 6. 五个步骤

1. 真人麦克风、权限恢复与停顿校准。
2. 真实语义模型接入与评分验收。
3. 长语音分段处理、进度、取消与恢复。
4. 训练状态与人工确认点持久化。
5. 网页知识生成服务与来源追踪闭环。

## 7. 产品经理需要决定的问题

- 步骤 2 真实冒烟前，需要确定一个 OpenAI-compatible 模型服务并由用户在本地安全配置 Key。
- 正式部署、账号和云端保存不在本轮范围。
