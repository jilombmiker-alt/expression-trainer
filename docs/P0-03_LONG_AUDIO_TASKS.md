# P0 第 3 阶段技术开发文档｜长语音任务、进度与恢复

> 配套文档：`PRD_P0_EXPRESSION_TRAINER.md`、`P0_TECHNICAL_ADAPTATION.md`、AI Agent 产品 Vibe Coding 通用技术栈手册。

## 一、阶段目标

- 支持 3–10 分钟表达，不依赖一次无限等待的 HTTP 请求。
- 展示上传、排队、转换、识别和完成进度，并支持取消、失败和刷新恢复。
- 不在 P0 引入外部任务队列或对象存储。

## 二、技术适配摘要

- 使用“创建任务 + 分段上传 + 提交 + 轮询结果”。
- 单用户本地服务以版本化 JSON 和原子写入持久化任务。
- FunASR 推理串行化，避免共享模型并发冲突。

## 三、技术栈与模型

- 浏览器 MediaRecorder 每 5 秒产生上传分段。
- Python 后端合并音频，ffmpeg 转 16kHz WAV，FunASR 生成转录和时间戳。
- P0 使用线程执行和轮询；生产并发达到阈值后再评估任务队列。

## 四、环境与配置

- 任务目录：`.p0-data/audio-tasks/`，已加入忽略列表。
- 单段上限 6MB，总大小上限 80MB，分段编号上限 600。
- 需要可用 ffmpeg 和 FunASR 才能完成真实识别。

## 五、项目结构

- `services/audio_tasks.py`：任务记录、原子写入、状态和清理。
- `services/p0_service.py`：任务 API、转码和后台识别。
- `web/speech-adapter.js`：任务请求和轮询。
- `web/training-session.js`：刷新后保留任务 ID。

## 六、数据、资产与状态

- 状态：`uploading → queued → converting → transcribing → completed`，以及 `failed / cancelled`。
- 记录包含 schema 版本、任务 ID、时间、真实内容类型、字节数、进度、结果和安全错误。
- 服务重启后处理中任务转为 `failed + retryable`；不伪装为继续运行。
- 取消或完成后清理音频分段和 WAV，保留任务记录与转录结果。

## 七、API / 工具设计

- `POST /api/audio/tasks`：创建任务。
- `PUT /api/audio/tasks/{id}/chunks/{index}`：顺序上传分段。
- `POST /api/audio/tasks/{id}/complete`：提交后台处理。
- `GET /api/audio/tasks/{id}`：查询状态和结果。
- `DELETE /api/audio/tasks/{id}`：取消任务。
- 所有错误使用统一错误结构。

## 八、Prompt 设计

- 本阶段没有 LLM Prompt。
- 热词来自当前训练卡概念，限制数量和长度。

## 九、验收界面或纵向切片

- 录音期间显示状态和取消入口；停止后显示排队、转码和识别进度。
- 刷新后依据任务 ID 查询后端，不用本地动画猜测完成。
- 失败显示可重试动作；取消明确说明不计分。

## 十、测试要求

- 自动测试：顺序上传、重启恢复、取消清理、未知 MIME、真实文件头和声明格式不匹配。
- 浏览器测试：受控任务元数据、统一错误读取和任务能力检测。
- 真人测试：3 分钟、10 分钟、处理中刷新、取消和服务重启。

## 十一、验收清单

- [ ] 3/10 分钟录音均不会无限等待。
- [ ] 进度对应后端真实状态。
- [ ] 取消后不会继续占用识别资源。
- [ ] 刷新和服务重启后任务不凭空消失。
- [ ] 伪造文件或格式不匹配被拒绝。
- [ ] 失败后知道如何重试。

## 十二、风险与待确认项

- 当前没有 3/10 分钟真人样本和设备性能数据。
- P0 线程任务不适用于多实例生产部署；生产化需要任务平台和对象存储评估。
- 已提交给底层推理的同步工作不能瞬间强杀，取消会阻止后续写入并清理文件。

## 十三、交接给下一阶段

- 已就绪：任务持久化、真实内容类型检查、统一错误、进度、取消、清理和重启失败恢复。
- 待交接：完成真人长录音，记录大小、转码时间、识别时间和错误情况。
